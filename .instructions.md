Repository instructions for ProjectManager agent

Purpose:
These repo-specific guidelines are used by the `Project Manager` agent when creating plans, PR templates, and release checklists.

Sprint cadence:
- 1 week sprints. Keep work small and incremental; prefer one-week scoped deliverables.

Branch naming:
- `feature/<short-description>` for new features
- `bugfix/<short-description>` for bug fixes
- `hotfix/<short-description>` for urgent production fixes
- `chore/<short-description>` for maintenance
- `release/<version>` for release branches

Commit messages:
- Use Conventional Commits (e.g. `feat: add user login`, `fix(auth): handle token expiry`).
- Include issue number where applicable: `fix: reset cache (#123)`.

Pull request expectations:
- Base branch: `main` (or `develop` if the project uses it).
- Title: short summary; body: motivation, changes, testing steps, rollout plan.
- Include checklist: implementation, tests added, docs updated, QA steps, migration notes (if any).
- Require passing CI and at least one reviewer approval before merging.
- Merge strategy: squash-and-merge for features/bugfixes; merge commit allowed for release/hotfix branches.

CI / Quality gates:
- Run unit tests, linters (format + static analysis), and basic integration tests on every PR.
- Enforce code coverage baseline (e.g., not decrease by more than 2%).
- Fail PR if linters or tests fail.

Release process:
- Tag releases as `vX.Y.Z` and include short release notes summarizing user-facing changes.
- Run release checklist: smoke test, migrations applied in staging, update changelog.

Testing & local commands:
- Run tests: `./scripts/test` or `pytest` (adjust per project).
- Run linters: `./scripts/lint` or `npm run lint`.

Roles & responsibilities:
- Requirements: define acceptance criteria and confirm scope.
- DevOps: maintain CI, releases, and deployment pipelines.
- QA: define test cases, perform exploratory and regression testing.

Templates and automation:
- Recommended: add a `.templates/PR_TEMPLATE.md` and `.templates/RELEASE_TEMPLATE.md` and let the `Project Manager` use them when drafting PRs and releases.

Notes for the agent:
- Ask for missing context (target branch, deadline, team members) before finalizing plans.
- Use 1-week sprint estimates by default, breaking work into daily or half-day tasks when possible.
